### 核心结论（后续若要动手，从这里接）

- **P0-1 阻塞调用进 async 运行时**：`handlers.rs:157` start_all 是 async fn 但同步调用 orchestrator，`orchestrator.rs:25-44` wait_ready 用 `thread::sleep` 最长 30s/服务，5 服务串行最多 150s 占满 tokio worker → 全站无响应。同类：`handlers.rs:93` list_services 的 TCP 探测、`handlers.rs:261` env_check_all 的 `Command::output()`。修法：`spawn_blocking` 或独立 blocking 池。
- **P0-2 running 状态失真**：`handlers.rs:97` 只查 `process.rs:20` 的内部 HashMap，不做真实存活校验 → 控制台重启后外部启动的服务全显示"未运行"，且 `Topology.tsx:15` 会把 `!running` 判成 down 导致拓扑图全红。修法：状态改三态 managed/detected/down，running 以端口+进程探测为准。
- **P1-1** `orchestrator.rs:115` start_all 未按 is_daemon 过滤，会把 biosphere-spatial 桌面 GUI 拉起来。
- **P1-2** `server.rs:124` CORS permissive + 无鉴权 → 任意网页可驱动本地 API 触发 build（run_cmd 来自 TOML，等价任意命令执行）。
- **P1-3** `process.rs:40-56` 非 Windows 只 kill shell，java/nginx 变孤儿（macOS 开发机直接踩中）。
- **P1-4** start 后从不 wait → 僵尸进程 + 崩溃无感知。
- **P1-5** `lib.rs:68-70` bind 失败 expect panic，UI 起来但 API 死，无单实例锁。
- **P1-6** `aimodels.rs:76-82` api_key 明文落盘，`handlers_ai.rs:13` 原样回吐给前端。
- **P2**：契约手工双写、AiAssistant.tsx 1020 行/26 useState、TS 侧 severity 有 "info" 但 Rust 没有、registry.rs:81 端口写 8080 实为 48085、MQTT 18830 既是己方监听又被当外部依赖、is_daemon 无保活实现、logs.rs:43 分块 count 可优化。

## 检测模型重构：端口由进程反查（已提交 commit ef2ee08）

- **进程是事实来源**：`process_pids`（pgrep -f，运行器特征）→ `listening_ports`（lsof/netstat 反查 PID 实际 LISTEN 端口）→ 检测与展示均用实际端口。配置 ports 仅保留编排就绪等待用途。

- **进程匹配用运行器特征不用项目路径**：`dfy-server.jar`/`ng serve`/`edgecd-daemon`/`biosphere-spatialdata-system`/`vue-cli-service|vite`。IDE 语言服务（Trae Helper）命令行含全部项目路径，用路径必误命中。
- **实测收获**：edgecd-daemon 除 8084/8085 外还监听 36750（动态端口）——反查模型把这种「配置里根本没写的端口」也如实显示，正是用户要的。
- detect_external 降级链：进程命中（主）→ 配置端口探测（兜底，兼容 nginx 多实例）→ Down。

## 环境检查去拓扑假设 + 就绪度修复（已提交 commit 98f75e2）

用户报告：部署就绪度 2/4（50%）、环境满足 2/4，dfy-ui 与 gateway-console 显示「环境警告」。根因全在 `environment.rs` 写死的部署机（Windows + nginx）假设，与端口问题是同一类错误：

- 就绪度公式 `running && healthy && env==pass` 被假警告拖成 50%。

修法（commit 98f75e2）：
- **服务实测在运行 ⇒ 环境事实上满足**：`check_service_env(def, running)`，运行中跳过拓扑假设项、只保留事实型外部依赖探测（MySQL/Redis/MQTT/上游——运行中也可能挂，warn 是真实的）。
- 未运行的前端：nginx 或 Node.js 任一可用即满足，不预设部署形态。
- Tauri：WebView2 检查仅 Windows；macOS/Linux 直接 pass。
- **附带发现并修复**：biosphere 反查出 50052（WorkBuddy Electron 宿主，命令行嵌项目路径被 pgrep 误命中）——pid 级过滤靠 `ps`，从 WorkBuddy 内启动的实例 ps 被 EPERM → 保守放行。修复：`listening_ports` 的 lsof 加 `+c0`，解析层按 COMMAND 列过滤噪音行（ps 不可用时的兜底防线）。

实测（真实 API）：env 5/5 pass；五服务 detected 全部 healthy；biosphere ports=[]（50052 已正确过滤）。前端就绪度将显示 4/4 = 100%。cargo test 26 passed、clippy 零警告、tsc 0 error。
